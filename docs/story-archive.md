# Staffroom Review — Story Archive & Removal Register

This document tracks stories removed, retired, superseded or otherwise taken out of active publication.

The archive is intentionally separate from the current story registry so a removed story remains retrievable without being treated as current editorial inventory.

## Removal rules

A story must be moved here rather than deleted from the editorial record when it has:

- been removed from a page or publication;
- been replaced by a substantially revised story;
- been withdrawn by its author;
- been paused for editorial, legal, factual or sourcing reasons;
- been superseded by a newer story covering the same ground;
- been permanently retired.

## Required archive fields

| Field | Purpose |
|---|---|
| Story ID | Permanent identifier retained from the master registry |
| Title | Last published/working title |
| Original URL | URL used while live, if any |
| Primary page | Where it belonged |
| Date removed | When it left active publication |
| Reason | Plain-language explanation |
| Removal category | withdrawn / superseded / factual / legal / editorial / duplicate / other |
| Replacement | Story ID/title that replaced it, where applicable |
| Republish possibility | yes / no / review |
| Notes | Context for future editorial decisions |

## Current archive

No stories are recorded as removed at the time this system is introduced.

Future removals should preserve the Story ID and should never reuse an archived ID for a new story.

## Relationship to verification

Archived stories remain searchable for overlap checks. A proposed new story may resemble a removed story, and that history can still matter when avoiding repeated angles, reintroducing disputed claims or accidentally recreating a retired concept.


## Registry rule

A removed story is not deleted from `data/story-registry.js`. Keep its original Story ID and set `editorialStatus: "archived"`; record the removal details here. This allows future story-overlap verification to include retired work.
