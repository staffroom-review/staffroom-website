# Staffroom Review — Events Architecture

## Purpose

Events is a specialist destination rather than another editorial story taxonomy.

It extends Staffroom Review into live programming while keeping the same visual identity and editorial discipline.

Primary URL:

`/events`

## Editorial role

Events should be used for:
- moderated conversations;
- practical sessions;
- Staffroom Salons;
- reading-room gatherings;
- selected future live collaborations.

The page should communicate a programme and a point of view, not resemble a generic conference listing.

## Page structure

1. Page title and proposition
2. Lead event/programme feature
3. Upcoming programme grid
4. Larger programme-principle feature
5. Event formats
6. Quiet closing CTA into The Staffroom Letter

The initial implementation deliberately uses proposed event concepts marked as "Coming soon" rather than inventing real dates, venues, speakers or ticket information.

## Design rules

- Reuse the approved Staffroom colour and typography system.
- Use the editorial Feature primitive where a major programme item benefits from image-led treatment.
- Use simple semantic event cards rather than introducing a second card system.
- Maintain the same spacing, rules and serif/sans hierarchy as the editorial pages.
- Mobile and tablet must derive from the same content model while changing density and stacking appropriately.
- Do not add event-specific visual effects that would make the page feel like a separate product.

## Navigation

Events is a direct top-level header destination.

`More` remains the specialist menu for:
- Podcasts
- Learning
- Visual Essays
- Blog

Events must not be duplicated inside More.

## Content status

The initial page contains editorial propositions only. Until real event information exists, these entries are not to be presented as confirmed events.

When real programming is commissioned:
- create/update the appropriate content record;
- verify names, dates, venues, links and other factual details;
- update navigation only when the destination is genuinely live.

## Approval gate

Events must receive desktop, tablet and mobile visual review before the specialist-navigation phase is considered complete.

After Events approval, the remaining specialist destinations can be implemented and the site-wide navigation verification can begin.
